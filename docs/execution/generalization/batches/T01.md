## Contract implemented

Placed beside `_check_observational_language` (module lines ~979-1017 in
the patched file):

```python
FIRST_PERSON_CRISIS_WINDOW_TOKENS = 3


def _has_first_person_high_crisis_hit(message: str) -> bool:
    message_lower = message.lower()
    for hit in _HIGH_MATCHER.iter_hits(message_lower):
        if _HISTORY_FIRST_PERSON_RE.search(hit.keyword):
            return True
        sentence_start = max(
            message_lower.rfind(ch, 0, hit.start) for ch in ".!?\n"
        ) + 1
        window = message_lower[sentence_start:hit.start].split()
        for token in window[-FIRST_PERSON_CRISIS_WINDOW_TOKENS:]:
            stripped = re.sub(r"^\W+|\W+$", "", token)
            if _HISTORY_FIRST_PERSON_RE.search(stripped):
                return True
    return False
```

**The helper's exact rule as implemented:**

- **Rule (a):** `_HISTORY_FIRST_PERSON_RE.search(hit.keyword)` — the matched
  HIGH keyword's own text (e.g. "kill myself", "end my life") contains a
  first-person token.
- **Rule (b):** a first-person token appears within
  `FIRST_PERSON_CRISIS_WINDOW_TOKENS` (3) whitespace tokens before
  `hit.start`.
- **Sentence boundary:** the last of `.`, `!`, `?` or `\n` before `hit.start`
  (via `max(rfind(...)) + 1`, identical to the parent's own
  `docs/execution/generalization/probes/t01_probe.py`); tokens before that
  boundary are excluded from the window regardless of raw token distance.
- **Window:** the last `FIRST_PERSON_CRISIS_WINDOW_TOKENS` (3) whitespace
  tokens of the in-sentence prefix before the hit; each token has leading/
  trailing non-word characters stripped (`re.sub(r"^\W+|\W+$", "", token)`,
  reusing the already-imported `re` module rather than adding a new
  `string` import) before being matched against
  `_HISTORY_FIRST_PERSON_RE`. In practice `_HISTORY_FIRST_PERSON_RE`'s own
  `\b` boundaries already tolerate most attached punctuation; the strip is
  implemented per the design's explicit instruction and is a no-op in most
  cases, never a false negative.

## BC-58 sibling search (report only, not fixed)

Per instructions: other early-return stages in `detect_crisis_level` that
could similarly mask a first-person HIGH hit.

- **Stage 1.5 (`short_casual` fast path, word_count < 8).** **Not
  reachable** for a genuine first-person HIGH hit, by construction: Stage
  1.5 only runs when Stage 1's `_check_keyword_crisis` already returned
  `None` (harm score < 4). A single HIGH keyword alone scores 10 points
  (docstring: "HIGH=10pts"), and the harm scan is negation-blind by design
  (R05 parent correction) — no discount can bring a real HIGH hit's
  contribution below 10 ≥ 4. So any message containing an actual HIGH
  keyword is already resolved at Stage 1 before Stage 1.5's code runs.
  Verified on the deployed functions: `"lol I want to die"` (5 words,
  `_is_casual_short_message` → `False` anyway) — `_calculate_harm_score`
  → `10.0 (['HIGH: want to die'])`; `_check_keyword_crisis` →
  `(CrisisLevel.MEDIUM, 'harm_score: 10.0 (1H, 0M, 0C)')`;
  `detect_crisis_level` → `MEDIUM`. Stage 1.5 never executes.
- **`_is_positive_state_report` downgrade (Stage 2, semantic CONCERN
  only).** **Not reachable** for the same structural reason: this downgrade
  only fires on a *semantic* CONCERN reached via Stage 2, itself only
  reached when Stage 1 returned `None`. A message carrying an actual HIGH
  keyword phrase is already routed at Stage 1 (≥4 points) and never reaches
  Stage 2. Verified on the deployed functions: `"I don't want to kill
  myself anymore, I'm doing so much better"` —
  `_is_positive_state_report` → `False` (moot; shown for completeness);
  `_calculate_harm_score` → `10.0 (['HIGH: kill myself'])`;
  `_check_keyword_crisis` → `(CrisisLevel.MEDIUM, ...)`;
  `detect_crisis_level` → `MEDIUM`. Stage 2 and the downgrade never
  execute.
- Both siblings are therefore not instances of the class this batch fixes
  (HIGH-hit masking) and are not touched.
