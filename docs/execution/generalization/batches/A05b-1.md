## 12. Open decision: why `build_integrated_fallback` is faked in two tests

`build_integrated_fallback(response, verdict, ...)` returns `None` only when
`_truncate_correction(verdict.correction)` or `_substantive_correction_text
(verdict.correction)` is empty — but `verify_grounding`'s own
`_is_advice_shaped`/safety-PSA/date-mismatch demotions apply that **same**
`_substantive_correction_text` check to `verdict.correction` before
`_apply_grounding_check` ever reaches its own flagged-verdict gate. So any
verdict that survives to the correcting branch (flagged, non-empty
correction, confidence above threshold) is, by construction, one for which
`build_integrated_fallback` cannot return `None` — it always produces at
least a standalone reply. The contract's "Builder None" outcome
(`grounding_fallback="none"`, draft unchanged) is real and load-bearing
(it's `_apply_grounding_check`'s defensive branch for a future stricter
builder, or a caller that skips `verify_grounding`'s own demotion), but it
is unreachable through today's real verifier pipeline. Both new/amended
tests that exercise it (`test_builder_none_ships_draft_unchanged`,
`test_f24_no_corrected_flag_when_builder_returns_none`) therefore fake
`build_integrated_fallback` directly — the same technique the existing
suite already uses to fake the LLM (`_StubModelManager`) — to drive that one
branch of the deployed function in isolation. Recorded here rather than
escalated: it is a test-construction fact about an already-committed pure
function (A05a, read-only to me), not a contract ambiguity or a missing
check.

## Contract for A05b-2

A05b-2 (buffered delivery in correct mode) inherits:

- **The mode/ctx seam it must add itself.** A05b-1 did not introduce any
  `ctx`-level mode cache — `_apply_grounding_check_for_delivery` still reads
  `GROUNDING_MODE` fresh (via `_apply_grounding_check`'s `mode=None` →
  `from config.app_config import GROUNDING_MODE` fallback) at the point the
  post-stream delivery call runs, which is late enough for A05b-1's
  whole-bubble-replacement contract but too late for buffering. A05_design.md
  calls for "read the mode once per turn into `ctx` at turn start (no
  mid-turn flip)" — that read-and-cache (e.g. a new `ctx.grounding_mode` set
  before the route loop starts) is entirely A05b-2's to add; nothing in this
  batch depends on it or blocks it.
- **What is still streamed visibly.** A05b-1 touched only the
  post-stream delivery call sites and `_apply_grounding_check`'s own
  fallback branch — it did not touch either route's per-chunk streaming
  loop. In `GROUNDING_MODE="correct"`, the full flawed draft is therefore
  still streamed live, chunk by chunk, exactly as A05_design.md's "Verified
  gaps" #1 describes (enhanced route's cumulative `message` events; agentic
  route's own loop) — A05b-1 only guarantees that the **final** chunk
  (post-review) is never draft-plus-suffix. A05b-2 must convert those
  per-chunk yields into progress-only chunks and hold the latest content so
  nothing unreviewed reaches the wire at all. This is the documented,
  accepted gap between A05b-1 and A05b-2 (A05_design.md Revision
  2026-09-13, last line: "acceptable because correct mode is not the
  default").
- **The revised-path delivery contract A05b-2 can rely on unchanged.**
  `_apply_grounding_check` returns `(revised_text, "")` for every case that
  ships a correction (integrated success or integrated fallback) and
  `(None, "")` for every case that doesn't; both call sites already do a
  single unconditional `if _gc_revised: <assign to both display/final>` with
  no remaining suffix branch. A05b-2's buffering wrapper can treat "the
  final chunk's content" as whatever `_resp_for_debug`/`display_output` and
  `final_output` hold after this call, with no suffix-shape special case
  left to preserve or remove.
- **Telemetry fields available for A05b-2's own receipt work:**
  `grounding_status` ∈ {unset, `"complete"`, `"failed"`, `"fallback"`,
  `"pending"`/`"timed_out"`/`"cancelled"` (log_only background path only)};
  `grounding_fallback` ∈ {`"spliced:<reason>"`, `"standalone:<reason>"`,
  `"none"`, absent (log_only, no-flag, or verifier-failure paths never set
  it)}. A05b-2/A05b-3 can key the cancel-storage-gate and parity-guard work
  off these without adding new grounding-outcome vocabulary.
