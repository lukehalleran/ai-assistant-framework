**Algorithm** (deterministic, no model call, no I/O, no logging anywhere in
this section):
1. `truncated = _truncate_correction(verdict.correction)`; if empty, or if
   `_substantive_correction_text(verdict.correction)` is empty → `None`.
2. Split a trailing `_PROPOSAL_CARD_RE` card off the response (same regex
   `integrate_grounding_correction` uses); the card is never scanned as
   prose and is reattached byte-for-byte at the very end of either result.
3. Split the remaining prose into sentence-preserving chunks that
   concatenate back to the input exactly (each chunk owns the
   whitespace/newline run before it).
4. Locate the claim: normalized (casefold + `normalize_ws`) containment
   first; if 0 or ≥2 sentences contain it, fall back to conservative
   content-token overlap (≥0.8 of the claim's distinct content words, only
   accepted when exactly one sentence clears the bar). 0 or ≥2 matches at
   either stage → not located / ambiguous.
5. Exactly one sentence located → **spliced**: replace only that sentence's
   core text with `"Correction: {truncated}"` (or the elevated lead), keep
   every other sentence and paragraph break untouched.
6. Not located / ambiguous → **standalone**: drop the prose entirely, return
   one short corrective reply (a lead sentence + the truncated correction +
   an offer to answer again), reattach the card.

## Contract for A05b

`A05b` (the atomic-switch batch that owns `gui/handlers.py`) can rely on:

- **Signature:** `build_integrated_fallback(response: str, verdict:
  GroundingVerdict, *, elevated: bool = False) -> Optional[IntegratedFallback]`.
  Call it exactly where the suffix is appended today
  (`gui/handlers.py:3920-3921` agentic, `:4575-4576` enhanced), passing the
  same `response`/`verdict`/`elevated` values already available there. It is
  synchronous (no `await`) and has no side effects — safe to call at any
  point in the delivery path, including after a timeout/cancellation from
  `integrate_grounding_correction`.
- **The two kinds:** `result.kind == "spliced"` means the correction was
  woven into the one sentence carrying the claim — every other sentence and
  paragraph break is byte-identical to the input prose. `result.kind ==
  "standalone"` means the flawed draft prose was dropped entirely and
  `result.text` is a short corrective reply that never contains any part of
  the original prose (beyond an intact trailing action-proposal card, which
  both kinds always keep).
- **Segmentation semantics (added round 1, F1):** a sentence/line break
  boundary is (a) any run of whitespace containing a newline — a heading, a
  bullet/numbered item, or an unpunctuated line is always its own chunk —
  or (b) terminal `[.!?]+` (+ optional closing quote/bracket) followed by
  end-of-line or by whitespace then a non-lowercase character; "$2.50",
  "3 p.m. on Monday" and similar never split. Chunks concatenate back to
  the input prose EXACTLY (leading whitespace/newlines included). A trade-
  off follows directly from (a): a claim a client line-wraps across a real
  newline (BC-64) now spans two chunks and cannot be located as ONE
  sentence, so it falls to `standalone` instead of `spliced` — still safe,
  since standalone never shows the claim either (see round 1 §16). A
  spliced bullet/numbered line keeps its marker (`"- "`, `"1. "`, etc.)
  ahead of the correction text.
- **None semantics:** `None` means "no substantive correction to deliver" —
  identical in meaning to today's verifier-failure path
  (`grounding_status="failed"`). A05b's fallback branch should treat a
  `None` return from `build_integrated_fallback` the same way it already
  treats a `None` verdict: ship the original draft unmodified, no marker,
  no suffix.
- **Card handling:** if `response` ends with a trailing action-proposal
  card (`_PROPOSAL_CARD_RE`), it is split off before any correction logic
  runs and reattached byte-for-byte at the end of `result.text` for BOTH
  kinds. A05b does not need to special-case cards when calling this
  function — the card is never rewritten, never treated as prose, and
  never lost.
- **Receipt fields for A05b to record** (never claim or correction text —
  `reason` is always one of a fixed set of short constant labels, unchanged
  by round 1's fixes — no new label was needed; the new minimum-token gate
  and word-bounded containment reuse `claim_not_located`):
  `grounding_status="fallback"`, plus `result.kind` (`"spliced"` /
  `"standalone"`) and `result.reason` (one of: `claim_located_containment`,
  `claim_located_overlap`, `claim_located_ambiguous`, `claim_not_located`,
  `empty_draft_prose`). These are safe to log/telemetry at INFO/DEBUG level
  as-is — they carry no user text.
- **No suffix-append path remains valid once this is wired in**: A05b must
  replace the `draft.rstrip() + suffix` shape entirely for the fallback
  case (the case this function exists for), not call this function
  alongside the old suffix builder.
