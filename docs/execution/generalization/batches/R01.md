## Requirement / defect ID, invariant, and why the source seam owns the fix

- Defect class: BC-37 "Processes fighting over shared state (script/test vs
  daemon)" (`docs/BUG_CLASSES.md`). A live Daemon holds a store (profile,
  facts collection, knowledge graph, proposals) in memory and re-saves it on
  its own cadence; a script that writes the same file on disk while Daemon
  runs gets silently clobbered or resurrected on Daemon's next save.
- Invariant: every `--apply` script that writes a Daemon-held store must
  refuse before performing any write when `utils.daemon_guard.daemon_running()`
  is true, and must never consult that check on a dry run.
- Why the source seam (this plan) owns the fix, not the class-guard plan:
  the class-guard plan owns scanner/detector/baseline; this plan owns the
  application code the baseline flags. `CGR-20260913-001` requested exactly
  this repair; the class-guard owner will remove the STALE rows and mark
  `confirmed_fixed` once integrated, per the request's acceptance contract.

## Contract implemented

Each of the three scripts gains:

1. A local `_daemon_running() -> bool` wrapper delegating to
   `utils.daemon_guard.daemon_running()` inside a `try/except Exception:
   return False`, matching the already-deployed pattern in
   `scripts/backfill_stance.py` (Phase B4, already guarded — one of the
   sixteen the request notes already carry the guard).
2. `main(argv=None)` (was `main()`), with `parse_args(argv)` replacing
   `parse_args()`, so the deployed function is directly testable without
   `sys.argv` monkeypatching.
3. `if args.apply and _daemon_running(): print("REFUSED: ..."); return 1`
   immediately after argument parsing:
   - `cleanup_stale_illness.py`: before `scan_profile`/`scan_chroma` (before
     any scan, per the parent's ready-record placement).
   - `graph_relation_normalize.py`: before `GraphMemory(persist_path=args.graph)`
     is constructed.
   - `reclassify_proposals.py`: before `MultiCollectionChromaStore(...)` is
     constructed, so a refused run never opens the Chroma directory (this
     was the parent's explicit requirement — importing the module already
     imports `config.app_config`, which does an import-time `mkdir`, but the
     store itself, the actual writer, is never opened on refusal).
4. `if __name__ == "__main__": sys.exit(main())` (was `main()`), so the
   refusal exit code is real for a CLI invocation. `sys` was already
   imported at module top in all three files — no new import needed.

Dry runs (`args.apply` False) never call `_daemon_running()` — the `and`
short-circuits — matching the request's "a dry run never consults the
guard's result for refusal."
