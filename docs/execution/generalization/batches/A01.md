## What changed in round 2 (F1–F6)

- **F1 — invert the default (a new route now genuinely defaults to
  protected)**. `api/launch_auth.py`'s `classify_request(scope,
  route_source)` replaces the old path-prefix `classify_path(path)`.
  `route_source` is the live FastAPI `app` (`create_app()` passes
  `route_source=app` into `add_middleware(...)`; `app.routes` is read
  **fresh on every request**, not snapshotted at construction, because
  `mount_admin_and_frontend` adds `/admin` and `/` after `create_app()`
  returns). Order: (1) `/admin`/`/admin/*` → unchanged admin policy; (2) the
  explicit public allowlist (`/health`, `/`) on GET/HEAD → Host-only; (3)
  `/api/*`, OR any path `Match`'d (`FULL` or `PARTIAL` — imported from
  `starlette.routing`; a route existing at that path is what matters, even
  with the wrong method) by a non-`Mount` route in the live table →
  **protected**: token required for **every** method including OPTIONS,
  Origin required for a mutating method — this also protects FastAPI's own
  `/docs`, `/redoc`, `/openapi.json`, `/docs/oauth2-redirect`, intentionally;
  (4) everything else (the `StaticFiles` catch-all, or a genuine 404):
  GET/HEAD public (Host only), a mutating method still needs token+Origin.
- **F2 — hardened shell response** (`api/app.py`'s `_serve_shell`). The
  index.html read now uses `with open(...)` (no unclosed file handle); the
  injected secret is `html.escape(secret, quote=True)`; the response adds
  `Cache-Control: no-store`, `X-Frame-Options: DENY`, and
  `Content-Security-Policy: frame-ancestors 'none'` — the token is never
  cached, and the page (with its approval-button UI) can't be framed for
  clickjacking.
- **F3 — no uncaught exceptions on hostile header values.**
  `_split_host_port` now requires `port_s.isascii() and port_s.isdecimal()`
  (both branches) instead of `.isdigit()` — `"²".isdigit()` is `True` but
  `int("²")` raises `ValueError`; a Host header like `127.0.0.1:²` now
  returns `(the-whole-string, None)`, which correctly fails the loopback-name
  check instead of crashing. `_origin_authority` now wraps the
  `SplitResult.port` access — which raises `ValueError` for an out-of-range
  port like `99999` — in the same `try/except` as `urlsplit`. Both fixes are
  covered by `TestLaunchAuthHelpers.test_loopback_host`
  (`is_loopback_host("127.0.0.1:²", 8000) is False`, no raise) and
  `.test_origin_allowlist_and_request_classification`
  (`is_allowed_origin("http://127.0.0.1:99999", allowed) is False`, no
  raise).
- **F4 — preflight rejection proven load-bearing.** A CORS preflight
  (`OPTIONS` with `Origin`, `Access-Control-Request-Method`,
  `Access-Control-Request-Headers: x-daemon-launch-token`) against
  `/api/session` gets **401 from `LaunchAuthMiddleware`, with no
  `access-control-allow-origin` response header** — because the middleware
  is outermost, `CORSMiddleware` never runs for this request, so a browser
  that sent this preflight would abort the real request rather than ever
  attaching the token cross-origin. New test:
  `test_cors_preflight_on_protected_route_rejected_before_cors_middleware`.
- **F5 — tests driven through the fully deployed app**
  (`create_app()` + `mount_admin_and_frontend()` with a `tmp_path` dist dir
  and a stubbed `gr.Blocks()`, via the new `_full_app(tmp_path, packaged=)`
  helper):
  (a) `test_every_route_defaults_to_protected` sweeps every non-`Mount`
  route+method live from `app.routes` with a valid Host+Origin but **no
  token** → 401, except the explicit allowlist
  `{("/health","GET"), ("/","GET"), ("/admin","GET")}` — the test asserts
  the *set of skipped entries equals the allowlist exactly*, so the skip
  list cannot silently grow if a future change makes something else public.
  (b) The same test then sweeps every **mutating** route+method (covers
  uploads, note-sync, settings, curation, models, session, actions) with a
  valid token but `Origin: http://evil.example` → 403, proving rejection
  happens before route code runs for every one of them, not just a sample.
  (c) `test_new_route_added_after_create_app_defaults_to_protected`
  registers `@app.get("/new-export")` **after** `create_app()` returns
  (mirroring how `mount_admin_and_frontend` itself adds routes): an
  unauthorized GET *and* an unauthorized POST (a method the route never
  declared — Starlette `Match.PARTIAL`, not `Match.FULL`) both 401; an
  authorized GET is 200 — this is the direct proof that the live-route-table
  read (not a snapshot) is what makes F1 work.
  (d) `test_public_get_paths_are_unauthenticated_but_still_host_checked`
  additionally asserts the shell response's three F2 headers.
  (e) `test_websocket_rejected_but_lifespan_passes_through` (merged with the
  existing websocket test) proves a `"lifespan"` scope reaches the inner app
  unmodified.
  The existing host-enumeration, stale-token, form-POST, executor
  0-then-1, SSE, `/health`, and `/admin` tests are kept, per instruction.
- **F6 — test determinism.** `test_mutating_route_origin_enforcement` now
  takes `monkeypatch` and pins
  `config.app_config.API_CORS_ORIGINS = ["http://localhost:5173"]` before
  building the app, rather than relying on `config/config.yaml` or a local
  override. `test_sse_chat_route_authorization`'s unauthorized-POST
  assertion is now exactly `== 401` (token is checked, and missing, before
  Origin is ever reached — never `403`), not `in (401, 403)`.

`api/app.py`'s other round-1 content (secret generation, minimal `/health`,
CORS-origins plumbing, static-mount ordering) is unchanged; only the
`add_middleware(...)` call gained `route_source=app` and `_serve_shell`

## Frozen contract for A02 (round 2: dev-proxy decision made by the parent)

- **Header**: `X-Daemon-Launch-Token` (`api.launch_auth.LAUNCH_TOKEN_HEADER`).
- **How the bundled page gets the token**: the explicit `GET /` route in
  `mount_admin_and_frontend()` serves `web/dist/index.html` with
  `<meta name="daemon-launch-token" content="<html.escape(secret, quote=True)>">`
  injected after `<head>` (or prefixed if absent), with
  `Cache-Control: no-store`, `X-Frame-Options: DENY`, and
  `Content-Security-Policy: frame-ancestors 'none'` (F2). A02's client reads
  this meta tag on load and attaches its value as `X-Daemon-Launch-Token` on
  every `/api/*` fetch, the SSE POST, uploads, action approval, and
  downloads. Never a cookie or query string.
- **Host rule**: the `Host` header hostname must be exactly `127.0.0.1`,
  `localhost`, or `::1`. A port in the Host header, if present, must equal
  the real ASGI connection's server port (`scope["server"][1]`) — never a
  hardcoded assumption.
  - **Amended by A01b (owner decision, 2026-09-14; see batches/A01b.md):**
    - The Host hostname may also exactly match an owner-trusted hostname or IP: `api.host`, when it is a specific non-wildcard address, plus the entries in `api.allowed_hosts`.
    - Matching is exact only (IP literals normalized, no suffix or wildcard); `0.0.0.0`, `::` and `*` are never trusted. The port rule is unchanged.
    - The Origin rule gains `http://<trusted-host>:<server port>` for those same hosts.
    - A trusted-Host caller receives the launch token from `GET /`, so the owner's network ACL is the trust boundary for those hosts.
    - Defaults (`api.host` 127.0.0.1, `allowed_hosts` []) keep the loopback-only behaviour above.
- **Origin rule**: required for POST/PUT/PATCH/DELETE only. (Corrected by the
  parent: a CORS preflight — OPTIONS — on a protected route is rejected by
  the token check with 401, before `CORSMiddleware` adds any CORS header, so
  a cross-origin page's browser aborts the real request; F4.) Must be the app's own origin or an
  entry in `config.app_config.API_CORS_ORIGINS`
  (default `["http://localhost:5173"]`). GET/HEAD reads still need only the
  token, not Origin.
- **Dev-proxy — PARENT DECISION (replaces round 1's three open options)**:
  cross-origin direct browser fetch to the API is **unsupported by
  design** — F4's preflight rejection is exactly the mechanism that makes a
  cross-origin fetch impossible, so round 1's option 1 (fetch the absolute
  backend origin directly, bypassing the Vite proxy) is **rejected**.
  Widening the Host allowlist to accept configured dev-CORS ports (round
  1's option 3) is **rejected** — the backend Host check stays strict,
  checked only against the real connection's own port. **Dev proxying is
  A02's to solve on the web side**: e.g. Vite's `changeOrigin: true` so the
  Host the backend sees is its own authority, with
  `Origin: http://localhost:5173` allowed via the existing
  `API_CORS_ORIGINS` entry. **How the Vite-served dev page obtains a token
  remains an OPEN A02 item** and must not introduce a tokenless path — this
  batch does not resolve it, only states the constraint.
- **Rejection shape**: JSON `{"detail": "<reason>"}`. `400` invalid Host;
  `401` missing/invalid/stale token, **or a CORS preflight on any protected
  route regardless of its Origin** (F4); `403` missing/null/mismatched/
  wrong-scheme Origin on a mutating request; `404` any `/admin*` path when
  packaged, indistinguishable from nonexistent.
- **`/admin` policy**: dev — reachable, Host-checked, Origin-checked on
  mutations, no token. Packaged — **404 outright**, before Gradio is
  reached, any credential.
- **`/health` policy**: `GET` only, Host-checked, no token/Origin, minimal
  `{"status": "ok"}`.
- **New-route default (F1, this round's fix)**: any route registered on the
  FastAPI app — under a router, directly via `@app.get(...)`, or by a
  future `mount_admin_and_frontend`-style post-`create_app()` addition — is
  `"protected"` (token on every method, Origin on mutating) unless it is
  explicitly in the two-entry public allowlist (`/health`, `/`) on
  GET/HEAD, or under `/admin`. A02 must not assume any new server route is
  reachable without the token merely because it isn't under `/api/`.
