## 7. The wrapper's exact semantics (`_buffer_grounding_draft(ctx, chunks)`)

Applied at both route dispatches only when `ctx.grounding_mode == "correct"`:

- **Held:** any chunk that is not a final chunk, not `is_progress`, and does
  not carry a `"thinking"` key — plain content, an `is_thinking` content
  chunk, or a bare string. Only the LATEST held chunk is kept; it is never
  yielded while held.
- **Passed through unchanged:** a dict with `is_progress` truthy; a dict
  carrying a `"thinking"` key (the duel path's shape — not produced by
  either route, kept defensive); a final chunk (dict with `"debug"`); every
  chunk after the first final chunk is seen (the turn is over).
- **Announcement:** the first time a chunk is held this turn, ONE progress
  chunk `{"role": "assistant", "content": "Checking facts…", "is_progress":
  True}` (`_GROUNDING_CHECK_PROGRESS_TEXT`) is yielded before holding.
  Exactly one per turn, regardless of how many chunks are subsequently held.
- **Flush:** if the wrapped generator is exhausted (`StopAsyncIteration`)
  with no final chunk ever seen, the last held chunk is yielded once, so an
  error/friendly/empty early return still reaches the user (verified against
  the real enhanced-route empty-response branch, handlers.py ~4290-4295, and
  directly against a synthetic generator).
- **Exception/cancellation:** if the wrapped generator raises — a plain
  exception, `CancelledError`, or `GeneratorExit` — nothing is flushed. The
  wrapper has no `except` clause around the `async for`, so the exception
  propagates unchanged out of the wrapper to its caller. `CancelledError` is
  not special-cased; it is simply an exception the wrapper does not catch,
  so it takes the same no-flush path as any other failure.
- **Closing the inner generator:** the `async for chunks:` loop and the
  post-loop flush both sit inside a `try:`; the `finally:` calls
  `await chunks.aclose()` unconditionally (guarded by `getattr(chunks,
  "aclose", None)` for defensiveness, though every real caller is always an
  async generator). This runs on every exit path — normal completion
  (already-exhausted, so `aclose()` is a documented no-op), a flush, an
  exception, or `GeneratorExit` from closing the wrapper itself — so the
  inner route's own cleanup (e.g. the enhanced route's storage `finally:`
  block) always still runs. Proven directly:
  `test_buffer_wrapper_reraises_without_flushing_on_exception` (inner's own
  `finally` still appends its marker when the wrapper re-raises) and
  `test_buffer_wrapper_aclose_closes_inner_generator` (explicit
  `wrapped.aclose()` while inner is suspended mid-turn still runs inner's
  `finally`).
