## Critical environment finding (read before trusting any prior local pytest run)

The shared pyenv interpreter's ambient `PYTHONPATH` is
`/home/lukeh/Daemon_v1/scripts/bin`. Something reachable from that directory
during Python's site initialization (before this checkout's root
`conftest.py` runs) imports the top-level `utils` package from
`/home/lukeh/Daemon_v1` and caches it in `sys.modules['utils']`. Because
Python's import system checks `sys.modules` before consulting `sys.path`,
this checkout's root `conftest.py` inserting this repo's root at
`sys.path[0]` **does not fix it for the `utils` package specifically** — only
for top-level names not already cached (`memory`, `config`, `core`, etc.,
verified unaffected). Reproduction:

```bash
python -c "import utils; print(utils.__file__)"
# -> /home/lukeh/Daemon_v1/utils/__init__.py   (WRONG checkout)
env -u PYTHONPATH python -c "import utils; print(utils.__file__)"
# -> /home/lukeh/daemon_exec/generalization/utils/__init__.py   (this clone)
```

This is exactly the five files A03a/A03b edit. Every command below was run
with `env -u PYTHONPATH` prepended (a pure environment-variable override of
this worker's own shell invocations — no file, global interpreter state, or
`/home/lukeh/Daemon_v1` content was read, written, or executed to produce
this fix). Without it, `tests/unit/test_profile_path_authority.py` fails to
collect against **this clone's** `utils/bootstrap.py` at all — it instead
tries to import a symbol from `/home/lukeh/Daemon_v1/utils/bootstrap.py`, a
path this worker is forbidden to touch or even usefully evaluate against.
This does not, by itself, prove earlier batches' evidence (A01/A02, which
do not import `utils.*` Python submodules) is invalid, but any future batch
whose focused tests import `utils.*` should apply the same `-u PYTHONPATH`
override and should re-verify prior `utils.*`-touching evidence gathered
without it. This is a pre-existing shared-environment condition, not
something this batch introduced or can fix (fixing it would mean editing
files under `/home/lukeh/Daemon_v1` or global interpreter/site config, both
out of scope and against the process rules).

## Contract implemented

`utils/bootstrap.py` gains exactly one new function (no behavior change to
any existing function): `get_user_profile_path() -> str`, evaluated at call
time:

1. `USER_PROFILE_PATH` from the environment, if set and non-empty — returned
   as-is.
2. Otherwise the authoritative default:
   `os.path.join(get_user_data_dir(), "user_profile.json")`.
3. Compatibility read: if the authoritative default does not exist but a
   legacy candidate does, return the legacy path (no copy/move/write) and log
   one WARNING (`daemon.bootstrap` logger, stdlib `logging`, no new
   dependency) naming both paths. Legacy candidates, in order: when frozen,
   `%APPDATA%/Daemon/user_profile.json`; in every mode, the old cwd-relative
   `data/user_profile.json`. A legacy candidate identical to the authoritative
   path is skipped. An explicit `USER_PROFILE_PATH` is never overridden by a
   legacy file (checked first, unconditionally).

The four resolvers now do `self.profile_path = profile_path or
get_user_profile_path()` and no longer define `_DEFAULT_PROFILE_PATH`
(removed from all four — grep-confirmed zero remaining references anywhere
in the repo). `memory/user_profile.py`'s `UserProfile.DEFAULT_PATH` is now
`None` ("use the authority"); `__init__` does `self.profile_path =
profile_path or self.DEFAULT_PATH or get_user_profile_path()`, so a
monkeypatched `DEFAULT_PATH` (e.g. `tests/unit/test_sep09_backup_recovery.py:36`)
still wins over both the explicit argument's absence and the authority. The
now-unused `import sys` was removed from `memory/user_profile.py` (the
`getattr(sys, 'frozen', False)` branch it supported was replaced by the
single `DEFAULT_PATH = None` line); ruff confirms no other reference to
`sys` remains in that file. No file outside the assigned list was edited to
implement this; `utils.bootstrap` imports nothing beyond the stdlib
(`sys, os, shutil, json, logging, pathlib, typing`) and does not import
`config`/`config.app_config`, preserving its documented side-effect-free,
import-order-independent contract.

No existing test file needed changes: none of
`test_user_identity.py`/`test_location_resolver.py`/
`test_institution_resolver.py`/`test_timezone_resolver.py`/
`test_user_profile.py`/`test_sep09_backup_recovery.py`/
`test_sep12_keyword_boundary_and_budget.py` had a fixture that actually read
a real file through the old cwd-relative default — every no-argument

## Deferred migration design (not implemented — compatibility batch only)

No migration code was written; `get_user_profile_path()` only reads, never
copies/moves/writes. A future migration batch should:

1. Dry-run report: enumerate every legacy-path hit across the resolvers'
   candidates, print source/destination and file sizes, write nothing.
2. Backup before apply: copy the legacy file (and any sibling stores it
   shares a directory with) to a timestamped backup before any write.
3. Idempotent: re-running after a successful migration is a no-op (detects
   the authoritative file already exists and skips).
4. Rollback: keep the backup path in the dry-run/apply report so a failed or
   unwanted migration can be reversed by restoring it.
5. Daemon guard: gate the apply step behind `utils/daemon_guard.py` so it
   never runs while the live app holds the store open.
6. Never run by tests: migration is an explicit, owner-invoked operation, not
   part of any test fixture or CI path.

## Frozen contract for A03b and later batches

- Function: `utils.bootstrap.get_user_profile_path() -> str`.
- Resolution order: `USER_PROFILE_PATH` env (non-empty) → authoritative
  `<get_user_data_dir()>/user_profile.json` if it exists → legacy candidate
  (frozen `%APPDATA%/Daemon/user_profile.json`, then cwd-relative
  `data/user_profile.json`) if the authoritative path is absent and a legacy
  one exists → authoritative path otherwise.
- All five profile consumers (four resolvers + `UserProfile`) call it as
  their zero-argument default; an explicit `profile_path=` always wins; for
  `UserProfile` a non-`None` `DEFAULT_PATH` (e.g. monkeypatched by a test)
  wins over the authority but loses to an explicit constructor argument.
- A03b (timezone behavior, Central fallback, `/etc/localtime`, Windows
  mapping, calendar-create integration) can rely on
  `TimezoneResolver.profile_path` already resolving through this authority;
  it should not reintroduce a separate profile-path default.
- Any future consumer of the user profile should call
  `utils.bootstrap.get_user_profile_path()` rather than hardcoding a path.
