## 7. Source edit

`core/prompt/builder.py` (25 changed lines: 24 insertions, 1 deletion):

- one new import, `from utils.retrieval_outcome import outcome_status`;
- the narrative try block (≈1064–1078): initializes
  `section_outcomes: Dict[str, Dict[str, str]] = {}` (the only place it is
  created — before the gather loop, since narrative runs first); on success
  records `outcome_status(narrative_state)` under `"narrative"`; on
  exception records `{"status": "failed", "reason": type(e).__name__}`; the
  existing `narrative_state = ""` fallback and both log lines are kept
  byte-for-byte; when `max_narrative <= 0` the block never runs, so
  `"narrative"` is simply absent (contract point 6's "not attempted → no
  entry");
- the gather loop's per-task branch: `raw = task.result()` is captured
  first, `outcome_status(raw)` is read from it BEFORE `gathered[name] = raw
  or []` (the empty-`OutcomeList` trap — an empty `OutcomeList` is falsy,
  so status must be read from the raw result, never from `raw or []`);
  `except (Exception, asyncio.CancelledError)` now distinguishes the two —
  `CancelledError` → `{"status": "unavailable", "reason": "cancelled"}`,
  any other `Exception` → `{"status": "failed", "reason":
  type(exc).__name__}` — with the existing `logger.warning` line kept
  byte-for-byte; the pending/timeout branch records `{"status":
  "unavailable", "reason": "timeout"}` before appending to
  `timed_out_names` (unchanged);
- the outer `except Exception as _gather_exc:` branch adds
  `section_outcomes.update({name: {"status": "failed", "reason":
  "gather_error"} for name in tasks.keys()})` — `.update()`, not `=`, so it
  does not clobber the `"narrative"` entry already recorded before the
  loop started; the existing `gathered = {name: [] for name in
  tasks.keys()}` line and the `logger.warning` line are unchanged;
- `prompt_ctx["_section_outcomes"] = dict(section_outcomes)` added
  immediately after `prompt_ctx["_task_timings"] = dict(task_timings)`
  (≈2099, now ≈2120) — the only place it is attached. The error-path
  `error_context` dict (≈2136+, carries `web_search_decision`) is untouched
  — it does not receive `_task_timings` either, so `_section_outcomes`
  correctly does not go there (contract point 7).

No other line touched: `gathered[name] = raw or []` is byte-for-byte what
`gathered[name] = task.result() or []` was (same expression, same
semantics — the gathered value the rest of the function consumes is
unchanged); trimming, dedup, rendering, timings, progress messages and logs
are all untouched; no other file was opened for writing.

## 18. Contract — how each of the 9 points is implemented

1. **`section_outcomes: dict[str, dict]` created beside `task_timings`.**
   `core/prompt/builder.py`, initialized `section_outcomes: Dict[str,
   Dict[str, str]] = {}` immediately before the narrative try block
   (≈1066), attached as `prompt_ctx["_section_outcomes"] = dict(section_outcomes)`
   next to `prompt_ctx["_task_timings"]` (≈2120). Proven by every test in
   `tests/unit/test_section_outcomes.py` (all read `result["_section_outcomes"]`).
2. **Done task: status read BEFORE the `or`.**
   `_raw = task.result(); _status, _reason = outcome_status(_raw);
   section_outcomes[name] = {...}; gathered[name] = _raw or []` — the
   status capture happens on `_raw` itself, before the `or []` flattening.
   Proven directly by `TestOutcomeListStatusReadBeforeFlattening::test_empty_failed_outcomelist_status_survives_flattening`
   (an empty `OutcomeList.failed("UPSTREAM_DOWN")` still records
   `{"status": "failed", "reason": "UPSTREAM_DOWN"}` even though
   `result["recent_conversations"] == []`).
3. **Done task that raised.**
   `except (Exception, asyncio.CancelledError) as exc:` branches on
   `isinstance(exc, asyncio.CancelledError)` — `CancelledError` →
   `{"status": "unavailable", "reason": "cancelled"}`; any other
   `Exception` → `{"status": "failed", "reason": type(exc).__name__}`.
   Proven by `TestSectionExceptionRecordsFailed::test_exception_recorded_failed_others_preserved`
   (`ValueError` → `{"status": "failed", "reason": "ValueError"}`).
4. **Pending at the deadline → unavailable/timeout.**
   The `else:` branch (task not in `done`) now also sets
   `section_outcomes[name] = {"status": "unavailable", "reason": "timeout"}`
   before appending to `timed_out_names`. Proven by
   `TestPendingTaskRecordsTimeout::test_pending_task_recorded_unavailable_timeout`
   (reusing `test_prompt_timeout.py`'s `expired_deadline` technique).
5. **Outer gather exception → every created task failed/gather_error.**
   `section_outcomes.update({name: {"status": "failed", "reason":
   "gather_error"} for name in tasks.keys()})` inside `except Exception as
   _gather_exc:`. Proven by
   `TestGatherExceptionMarksAllFailedGatherError::test_asyncio_wait_raising_marks_every_created_task`
   (monkeypatches `core.prompt.builder.asyncio.wait` to raise; all three
   created tasks — `recent`, `user_profile`, `web_search` — read
   `failed`/`gather_error`).
6. **Narrative outcome recording.** Exception → `failed`/class name
