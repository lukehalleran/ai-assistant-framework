## 6. Exact semantics implemented

**F1 — when the wrapper flushes.** `_buffer_grounding_draft`'s exhaustion
flush (no final/debug chunk ever seen) is now conditional on
`flush_on_exhaust()`, a zero-arg callable defaulting to always-`True`. The
enhanced dispatch passes no override (keeps A05b-2's unconditional flush —
every enhanced early return is a reviewed warning/error, never a draft). The
agentic dispatch passes `flush_on_exhaust=lambda: ctx.handled`: a HANDLED
early return (degenerate-watchdog, friendly-API-error — both set
`ctx.handled = True` before returning) still flushes its warning exactly as
A05b-2 shipped it; an UNHANDLED exit (`_run_agentic_search`'s internal
`except Exception`, which logs "falling back to standard" and returns with
`ctx.handled` False) now drops the held partial draft instead of flushing it
onto the wire ahead of the enhanced route's reviewed answer that follows.

**The reviewed-delivery flag.** `review_delivered = False` initialized
before `_run_enhanced`'s `try:`; set to `True` immediately before `yield
_enh_final_chunk` (the one point the reviewed text is final). Nothing else
sets or reads it except the `finally:` gate below.

**The storage gate, per mode and exit path** (`_correct_mode =
ctx.grounding_mode == "correct"`, evaluated once in `finally:`):
- **correct + success** (reviewed chunk delivered, no exception):
  `review_delivered` is `True`, `_base_exc_active` is `False` → normal
  dispatch path runs, storing the reviewed `final_output`.
- **correct + streaming exception** (`except Exception`, e.g. the
  orchestrator stream raises after partial content): `review_delivered`
  stays `False`, `_base_exc_active` stays `False` → the `elif` guard
  `not (_correct_mode and not review_delivered)` is `False` → NO dispatch.
  No new receipt vocabulary; the existing failure debug record (mode
  `"failed"`) remains the trace, unchanged.
- **correct + cancel/BaseException** (`CancelledError`/`GeneratorExit`
  unwinding through the frame, caught by the new `except BaseException:
  _base_exc_active = True; raise` clause — detected via that flag, not
  `sys.exc_info()`): dispatches NO assistant-text storage; instead sets
  `ctx.telemetry["delivery"] = "cancelled_before_review"` and calls
  `_write_turn_telemetry(ctx, "enhanced", _get_session_id(orchestrator),
  model_name-if-set, 0, response_text="")` so the turn still leaves one
  receipt, carrying no draft text (`response_text=""`). This runs whether
  the cancellation lands before ANY content streamed or after partial
  content — both are "cancel before review completes" in the design's
  sense (review never reached the reviewed-chunk yield).
- **log_only / off**: `_correct_mode` is `False` in both branches of the new
  `if/elif`, so execution falls to the original unconditional `elif
  final_output and len(user_text.strip()) > 0 and not is_error_response:` —
  byte-identical to pre-A05b-3 behavior, including under cancellation
  (verified by `test_log_only_cancel_keeps_storage_call`).

**The `delivery` receipt.** The only new telemetry key
(`ctx.telemetry["delivery"]`), one value: `"cancelled_before_review"`.
`_hook_turn_telemetry` (`core/orchestrator.py`) merges `ctx.telemetry` into
the recorded row unconditionally, so the key lands directly in the JSONL
row. Verified: exactly one row per cancelled turn, `row["delivery"] ==
"cancelled_before_review"`, and no row (or any other receipt value) contains
the draft token. A normal correct-mode completion's row has no `delivery`
key at all (unchanged).

**The parity guard** (enhanced, log-only, mirrors the agentic one at
`_answer_bodies_agree` call ~4082): inserted immediately before
`_dispatch_storage` inside the (already-gated) dispatch block, so it never
runs when the gate above already skipped storage. Compares
`_resp_for_debug` (the displayed text — in scope whenever this block is
reached, since `review_delivered` being relevant implies the try body
already computed it; a defensive `'_resp_for_debug' in dir()` guard falls
back to `final_output` otherwise) against `response_to_store` (post
`_sanitize_response_text` + `_strip_echoed_headers`). Never mutates either
text; logs `"[HANDLE_SUBMIT] Enhanced display/storage body mismatch — ..."`
on divergence. Runs in every mode reached (log_only, off, and correct when
not gated) — matching "runs in all modes" from the contract, understood as
every mode whose turn actually reaches a dispatch attempt.

Test technique note: the contract's suggested test technique ("patch
`_sanitize_response_text` to alter the body") does not isolate a
display/storage divergence here, because `_resp_for_debug` (the DISPLAY
text) is itself computed via `_sanitize_response_text(display_output or
final_output)` earlier in the try body (~line 4564) — patching that
function moves both sides identically and they'd still agree with each
other. `_strip_echoed_headers` is applied ONLY to the stored copy (never to
`_resp_for_debug`), so `test_enhanced_parity_guard_warns_on_divergence`
patches that instead to force a genuine divergence; the silent-control test
leaves it unpatched.

## 11. Contract for A05c

Delivery/storage invariants that now hold, per route and mode:

- **Enhanced, correct mode:** `display_text == stored_text == final_text`
  holds on the SUCCESS path (unchanged from A05b-2/A05b-1). On a
  cancellation or a mid-stream exception, NO text is stored at all — the
  atomicity question ("do display/stored/indexed agree") is moot because
  there is no stored/indexed side to compare; only a `delivery` or failure
  receipt exists. The parity guard (log-only) now also runs on the enhanced
  success path in every mode, matching the agentic route's existing guard.
- **Enhanced, log_only/off:** byte-identical to pre-A05b-3 in every
  exit path, cancellation included (explicit control test).
- **Agentic route:** unaffected by this batch's storage-gate work (A05b-3
  did not touch `_run_agentic_search`'s own storage dispatch or its
  existing parity guard) except for F1: an unhandled internal failure no
  longer leaks a partial draft chunk onto the wire before falling through to
  the enhanced route. The agentic route's OWN cancel-during-review gap (if
  any — A05b-3 did not audit `_run_agentic_search` for an equivalent
  `verify_grounding`-during-cancel scenario, since its storage dispatch
  happens inline before `ctx.handled = True`, not in a `finally:`) is
  outside this batch's owned regions and unexamined here.
- **Receipt vocabulary:** exactly one new value, `delivery =
  "cancelled_before_review"`, written only for enhanced + correct mode +
  BaseException. No other route or mode can produce it.
- **Open for A05c's atomicity matrix:** whether the AGENTIC route has an
  analogous cancel-before-review storage gap (its `_dispatch_storage` call
  sits after `yield _final_chunk`, not in a `finally:`, so a cancellation
  during the agentic verify_grounding call — `_apply_grounding_check_for_delivery`
  is called inline in `_run_agentic_search` too, per the parent-verified
  facts — may or may not already avoid dispatching storage simply because
  the cancellation propagates past the dispatch call before it runs; this
  was not traced end-to-end here); the full matrix of route × mode ×
  integrate-on/off × integrator-fail/timeout × verifier-failure × cancel
  cells the design's A05c batch owns; whether `off` mode's grounding-disabled
  path needs any receipt at all (currently: none, unchanged).
