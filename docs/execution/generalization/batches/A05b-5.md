## 6. Verification: the gap is not mode-gated

Nothing between the agentic route's final `yield _final_chunk` and its
(then-sequential) storage dispatch reads `ctx.grounding_mode` — the
generator suspends at `yield` regardless of mode, and only resumes past it
when the consumer asks for the next item. A consumer that stops pulling
right after the final chunk (the same pattern the A05b-3 D1 / A05b-4
teardown tests use) abandons the wrapped generator at that suspended
yield in log_only exactly as in correct mode; the event loop's
async-generator finalizer later closes it via `GeneratorExit`, which
propagates without resuming the sequential code. `test_log_only_agentic_teardown_after_final_chunk_stores_once`
(§4) confirms this failed on the unedited source (0 storage calls) and
passes after the fix. `_start_background_grounding` (reached inside
`_write_turn_telemetry`) is called with the same arguments in the same
relative position regardless of which of the two call sites invokes the
closure — log_only's background grounding scheduling is unaffected.

## 11. Storage/receipt semantics per agentic exit path

- **Normal completion** (consumer keeps iterating past the final chunk):
  `review_delivered = True` before the yield; the yield resumes normally;
  `_dispatch_agentic_review_storage()` runs on the normal path, sets
  `_agentic_storage_dispatched = True`, `ctx.handled = True`,
  `ctx.storage_dispatched = True`; `return`. `finally:` then sees
  `_agentic_storage_dispatched` already True, so its `elif` does not
  fire — storage dispatched exactly once.
  Evidence: `test_correct_mode_happy_path_stores_reviewed_text` (enhanced,
  pre-existing) and the new `test_agentic_correct_mode_happy_path_stores_reviewed_text_once`
  (agentic) — `storage.assert_called_once()`, stored text == displayed
  text, one turn row, no `delivery` key.
- **Teardown AT OR AFTER the reviewed final chunk** (GeneratorExit thrown
  into the suspended `yield _final_chunk` by the async-generator
  finalizer, once the consumer stops pulling after receiving that chunk —
  the BC-45 gap this batch closes): `except BaseException` sets
  `_base_exc_active = True` and re-raises unchanged; `finally:`'s first
  `if` is False (`review_delivered` is True), so no cancel receipt; the
  new `elif review_delivered and not _agentic_storage_dispatched:` is
  True, so `_dispatch_agentic_review_storage()` runs there instead — one
  dispatch, one turn row, no `delivery` key. Applies in EVERY mode
  (log_only/off included — §6), not just correct mode.
  Evidence: `test_agentic_teardown_after_reviewed_final_chunk_writes_no_cancel_receipt`
  (correct mode) and `test_log_only_agentic_teardown_after_final_chunk_stores_once`
  (log_only) — both `storage.assert_called_once()` with the reviewed/draft
  text, one turn row, no `cancelled_before_review` and no `delivery` key.
- **Cancel/BaseException BEFORE the reviewed final chunk** (A05b-4,
  unchanged by this batch): `review_delivered` is still False;
  `finally:`'s first `if` fires (`_correct_mode and _base_exc_active and
  not review_delivered`) — writes exactly one `delivery=
  "cancelled_before_review"` receipt, `response_text=""`; the new `elif`
  cannot also fire (`review_delivered` is False). No assistant text
  stored — the sequential dispatch code, earlier in program order than
  the point of cancellation, never ran.
  Evidence: `test_agentic_cancel_before_review_gate_and_receipt`
  (unmodified, still green) — `storage.assert_not_called()`, one row with
  `delivery == "cancelled_before_review"`, no draft token anywhere.
- **Internal `except Exception` fallback** (agentic fails mid-stream with
  a plain Exception, not a cancellation — falls through to enhanced):
  `_base_exc_active` stays False; `review_delivered` stays False (never
  reached the yield in this failure shape, or the closure never ran if it
  did) — neither `finally:` branch fires; no agentic receipt, no agentic
  storage; the enhanced route (already fixed by A05b-3) owns the turn's
  one delivery.
  Evidence: `test_agentic_exception_fallback_writes_no_agentic_receipt`
  (unmodified) — exactly one telemetry row (enhanced's), no `delivery`
  key.
- **log_only / off, cancel with storage already dispatched** (unaffected
  control, unchanged from A05b-4): `_apply_grounding_check_for_delivery`
  never awaits `verify_grounding` synchronously in these modes, so the
  normal path already dispatched storage before any cancel; a cancel
  after that point is a no-op for storage/receipts.
  Evidence: `test_log_only_agentic_cancel_keeps_storage_call` (unmodified)
  — `storage.assert_called_once()`, no `delivery` key.

**Double-dispatch impossibility (mirrors A05b-4 §11's double-receipt
argument):** the normal path and the `finally:` `elif` are mutually
exclusive by construction via `_agentic_storage_dispatched` — the flag is
set inside the same closure both call sites invoke, so whichever call
site runs first flips it and the other (if reached) becomes a no-op
condition. Proven by test: `test_agentic_correct_mode_happy_path_stores_reviewed_text_once`
asserts `assert_called_once()` (not twice) on the path where the normal
call runs and `finally:` still executes afterward.

**Never both a cancel receipt and storage:** the two `finally:` branches
are `if` / `elif` on complementary conditions (`not review_delivered` vs.
`review_delivered`) — structurally impossible to hit both. No test
observed both a `delivery` key and a non-empty storage call on the same
turn.
