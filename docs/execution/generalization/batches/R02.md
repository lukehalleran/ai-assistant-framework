## Requirement / defect ID, invariant, and why the source seam owns the fix

- Defect class: BC-01 "Bare-substring keyword matching" (`docs/BUG_CLASSES.md`).
  `_is_conversational` tested `"conversational" in str(tone).lower()` — the
  same mechanism as BC-01's first incident (`"crisis" in
  str(CrisisLevel.CONVERSATIONAL)`), just with a different keyword and a
  helper that (unlike the incident) currently produces the right *result*
  for the tone values actually seen in this tree, because no non-CONVERSATIONAL
  member's string form happens to contain the substring "conversational".
  The mechanism is still unsound: any tone-like value whose lowered string
  form merely *contains* the word (a plain string, a future enum, a debug
  label) is wrongly admitted.
- Invariant (parent contract): normalize `tone` — an `Enum` member to its
  `.value`, anything else to itself — then compare
  `str(normalized).strip().lower() == "conversational"` for **equality**,
  never containment. Keep accepting `CrisisLevel`, `ToneLevel`, and plain
  strings. `observe()` must never raise.
- Why the source seam (this plan) owns the fix, not the class-guard plan:
  the class-guard plan owns scanner/detector/baseline; this plan owns the
  application code the request flags. `CGR-20260913-004` requested exactly
  this repair.

## Contract implemented

`core/safety_canary.py`'s `_is_conversational` (`SafetyCanary`, a
`@staticmethod`):

```python
normalized = tone.value if isinstance(tone, Enum) else tone
return str(normalized).strip().lower() == "conversational"
```

(`from enum import Enum` added to the module's imports.) This is exactly the
parent's contract: an `Enum` member normalizes to its `.value`; anything
else (a plain string, `None`, an int, a bare object) normalizes to itself,
then `str(...).strip().lower()` is compared for **equality** to
`"conversational"` — never substring membership. `observe()`'s existing
broad `except Exception: return None` (so a canary must never break a turn)
is untouched and still wraps the call.
