  `_CONCERN_MATCHER`, `_EVENT_MATCHER`):

    placed immediately after the `OBSERVATIONAL_MARKERS` set it compiles.
- Anchor #29: `marker_count = sum(1 for marker in OBSERVATIONAL_MARKERS if
  marker in message_lower)` replaced with `sum(1 for _ in
  _OBSERVATIONAL_MATCHER.iter_hits(message_lower))` — `iter_hits()` yields
  at most one hit per keyword, so this counts DISTINCT markers with a
  boundary-respecting hit, exactly the "distinct marker" semantics the raw
  membership sum approximated. Multi-word phrases (containing a space) keep
  substring semantics unchanged inside `compile_keyword_matcher`; only bare
  single-word markers (`millions`, `society`, `news`, `article`,
  `statistics`, `civilians`, `residents`, `citizens`, `protests`,
  `protesters`, `authorities`, `officials`, `policies`, `regulations`,
  `legislation`, `thousands`) become boundary-matched.
- Anchor #30: the raw `if "overwhelmed" in message_lower:` /
  `any(marker in message_lower for marker in positive_markers)` block
  replaced with:
  ```python
  overwhelmed_hit = next(_OVERWHELMED_MATCHER.iter_hits(message_lower), None)
  if overwhelmed_hit and not is_negated(message_lower, overwhelmed_hit.start):
      if not _OVERWHELMED_POSITIVE_MATCHER(message_lower):
          score += 2
          ...
  ```
  `is_negated` (from the chokepoint, imported beside `compile_keyword_matcher`)
  is checked at the match position, so a chokepoint-recognized negation cue
  before "overwhelmed" suppresses the harm add. The exemption list is now
  boundary-matched via `_OVERWHELMED_POSITIVE_MATCHER`, so `'happy'` no
  longer matches inside `"unhappy"`.
- No vocabulary entry was added to or removed from `OBSERVATIONAL_MARKERS`
  or the positive-marker exemption list (BC-76: no phrase-append).
  `utils/trigger_match.py` was not edited.

### Chokepoint negation gap (anchor #30, not fixed — recorded honestly)

Directly verified with `utils.trigger_match.is_negated`, both before and
after this patch:

```
is_negated("i'm not overwhelmed", <match_start>)        -> False
is_negated("i'm no longer overwhelmed", <match_start>)   -> False
is_negated("i won't be overwhelmed", <match_start>)      -> True
is_negated("i will never feel overwhelmed again", ...)   -> True
is_negated("without feeling overwhelmed", ...)           -> True
is_negated("i'm not going to be overwhelmed", ...)       -> True
```

`utils.trigger_match.NEGATION_CUE_RE`'s own module docstring states: "Bare
'not' is not itself a cue — it only counts inside the listed cue forms
('do not', 'not going to', 'not asking (you) to', ...)"; there is likewise
no "no longer" cue form. So bare "not X" and "no longer X" are a known,
pre-existing chokepoint gap, not something this batch introduced or could
close without editing `utils/trigger_match.py` (out of this batch's
ownership) or adding a local phrase-based workaround in `tone_detector.py`
(ruled out by BC-76 and by the contract's explicit instruction: "if it does
not cover a form, record that honestly rather than extending the
chokepoint"). Both forms are covered by dedicated, passing tests
(`test_bare_not_overwhelmed_is_a_known_uncovered_form`,
`test_no_longer_overwhelmed_is_a_known_uncovered_form`) that assert the
CURRENT (unfixed) behavior, so a future chokepoint fix will need to update
these two tests deliberately rather than silently regress past them.
