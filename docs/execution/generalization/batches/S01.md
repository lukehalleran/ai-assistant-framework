## 2. Requirement/defect ID and invariant

- BC-21 (compare/coerce on the serialized form) sibling of F03/A04's
  `core/grounding_check.py::_parse_verdict`; BC-47 (failure/not-run
  collapsed into a valid result) — a rejected parse must be recorded as a
  classifier failure, never as a "no search needed" verdict.
- Invariant (parent contract): the top level must be a JSON object;
  `should_search` (bool) and `search_terms` (list of str) are REQUIRED —
  absent or wrong-typed rejects the whole payload; every other taught field
  is OPTIONAL — absent keeps its documented default, present it must have
  its taught type or the payload is rejected. Any violation returns `None`
  with exactly one warning naming only the field and its Python type — never
  the query, reason, or search-terms text.
- Why the source seam owns the fix: `LLMSearchTriggerResponse.parse` is the
  single place that turns the trigger LLM's raw JSON text into a
  `LLMSearchTriggerResponse`; it called `bool()`, `float()`, `int()`, `str()`
  directly on untrusted model output, so `"should_search": "false"` silently
  became Python `True` (`bool("false")` is `True`), and a string
  `search_terms` silently became a list of single characters
  (`list("abc") == ['a','b','c']`).
