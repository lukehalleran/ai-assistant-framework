## 4. Behaviour contract

- Keys: `fallback_claim_overlap_threshold: 0.8` (min fraction of a claim's
  distinct content tokens that must reappear in exactly one sentence for a
  reworded claim to be located) and `fallback_min_claim_tokens: 3` (claims
  with fewer content tokens are located by word-bounded containment only).
- Default-config behaviour is byte-identical to the former hardcoded
  `0.8`/`3` — every pre-existing test in
  `tests/unit/test_grounding_integrated_fallback.py` (436 lines, unmodified)
  stayed green (see §6/§7).
- `_locate_claim_sentence` stays a pure function: `overlap_threshold` and
  `min_claim_tokens` are required keyword arguments with no module default,
  so it is directly testable with explicit values independent of config
  wiring (see `TestLocateClaimSentenceExplicitParams`).

## 5. Out of scope — reviewed, not externalized

| `_OVERLAP_STOPWORDS` | A fixed content/function-word classification set, not a bounded numeric threshold — per the file's own BC-76 note distinguishing a threshold from a vocabulary list, this stays a structural definition, not something to expose as a tunable. |
| `_SPLICE_LEAD`, `_SPLICE_LEAD_ELEVATED`, `_STANDALONE_LEAD`, `_STANDALONE_LEAD_ELEVATED`, `_STANDALONE_TAIL` | User-facing wording, not a tunable value. |
| `_MAX_CORRECTION_CHARS` | A structural truncation cap shared by both the spliced and standalone builders; not one of the two claim-location thresholds this batch's contract names. |
