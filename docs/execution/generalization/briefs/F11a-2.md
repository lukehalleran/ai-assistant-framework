CONTRACT (staged replacement, CM-07)
1. Find the item exactly as today; not found → False (unchanged); `_ensure_collection` False → False (unchanged).
2. If the found item has no `id`, or the collection handle is missing, do NOT write: log one warning (labels only) and return False. (Today this path silently stores a duplicate.)
3. Write the new version FIRST: `new_id = self.store_thread(thread)`. Catch the TYPED `StoreWriteError` → log (labels only) and return False with the OLD document untouched. A None `new_id` (skip) → return False with the old document untouched.
4. Only after a confirmed write, delete the old document. If that delete raises → best-effort delete of `new_id` (rollback; its own failure is logged, labels only, not raised) and return False, so the store is left holding the old version only (or, if the rollback also failed, both versions — record that residual case as a limitation).
5. Return True only after the write and the delete both succeeded.
6. `touch_thread`, `enforce_cap`, `get_top_threads` and every caller are unchanged; they now see an honest True/False.
7. The existing outer except and its log line stay for any other failure (e.g. `list_all` raising `RetrievalError`) → False.
8. Scanner shape: prefer typed excepts (`StoreWriteError`) for the write step. The delete step talks to a raw collection whose exceptions are untyped, so a broad catch there is expected for the rollback. If any gate scanner reports a NEW finding on your edit, STOP and escalate to the parent with the code and the scan row — do not restructure around it.
9. Privacy: labels and class names only in every new log line.
