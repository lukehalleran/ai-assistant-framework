CONTRACT
1. `_background_store_interaction` returns the F13b label (`storage_failed_label`) on a failed store, and None on success, skip or the outer-except path. Its log lines, transcript metadata and single `log_interaction` call are unchanged.
2. The helper receives the ctx and the value `_dispatch_storage` returned. It acts ONLY when that value is a real `asyncio.Task` (`isinstance(value, asyncio.Task)`); anything else is ignored with no attribute set. For a real task:
   - (a) set `ctx.storage_task = task`;
   - (b) register ONE done-callback that:
     - reads `task.result()` (skipping a cancelled task or one that raised);
     - on a label, sets `ctx.telemetry["storage_failed"]` when `ctx.telemetry` is a dict, and `ctx.debug_record["storage_failed"]` when `ctx.debug_record` is a dict (the delivered object, updated in place);
     - never raises (try/except with a debug log).
     - It is registered BEFORE any combined waiter is created, so it runs first.
3. `_write_turn_telemetry`:
   - `telemetry=` passes `ctx.telemetry` itself whenever it is a dict (even an empty one), and `{}` otherwise.
   - `telemetry_task=` is:
     - `ctx.grounding_task` when there is no real storage task (today's behaviour exactly);
     - the storage task when there is no grounding task;
     - when both exist, ONE combined future over both, created after `_start_background_grounding` (e.g. `asyncio.gather(grounding_task, storage_task, return_exceptions=True)`).
   - Exactly one turn row per turn. The hooks still run immediately.
   - The callers must call the helper before `_write_turn_telemetry` at every site. Read each site and record the order.
4. `_hook_turn_telemetry.write_completed` copies `storage_*` keys as well as `grounding_*`. No other change.
5. No user-visible change: every yielded chunk, the `complete` payload and the chat text are unchanged.
6. Record as limitations:
