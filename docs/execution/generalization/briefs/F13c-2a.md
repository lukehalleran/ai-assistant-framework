CONTRACT
1. Fixed user-visible text, exactly "Memory save failed". Never render the `storage_failed` label or any server text. No toast/notification, and no change to chat messages.
2. State and reducer:
   - `storageNotice: boolean` (initial false);
   - an action `{ type: 'storage_notice'; show: boolean }`;
   - `stream_started` sets it to false; `cleared` resets it (through `initialState`).
3. `send`:
   - Capture the `complete` event's debug object.
   - After the stream ends (after `stream_ended`), when the stream was not aborted and this send is still the current one:
     - (a) if `completeDebug?.storage_failed` is a non-empty string → show the notice now and schedule its clear after 4000 ms;
     - (b) otherwise, if `completeDebug` is an object (not null/undefined) → schedule ONE follow-up after 2500 ms: fetch `/api/debug` via `api.getDebugRecords()` or `authorizedFetch`, take the LAST record, and if this send is still current and its `storage_failed` is a non-empty string → show the notice and schedule the 4000 ms clear.
   - Any fetch or parse error is ignored silently: no `error` state, no console noise beyond what the codebase already does.
   - A per-send counter ref makes pending follow-ups and clears stale. A new `send` and `clearAll` bump it and clear pending timers. One unmount-cleanup effect clears timers.
   - Name the delays as constants.
4. ProgressIndicator:
   - new optional prop `storageNotice?: boolean`;
   - while streaming: exactly as today (the notice never shows while streaming);
   - not streaming with `storageNotice` true: render the same Group position with a small dimmed `Text` "Memory save failed" and `role="status"` (no loader, no elapsed timer);
   - not streaming without it: return null as today.
