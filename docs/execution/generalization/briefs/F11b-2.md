CONTRACT
1. `update_status` (staged replacement, CM-07; follow F11a-2's `_replace_stored_thread`):
   - skip → False and not-found / missing doc id → False (unchanged);
   - a missing collection handle → do NOT write; log one warning (labels only) and return False (today this path stores a duplicate);
   - write the new version FIRST: `new_id = self.store_proposal(proposal)`; catch the TYPED `StoreWriteError` → log (labels only) and return False with the OLD document untouched; a None `new_id` → return False with the old document untouched;
   - only after a confirmed write, delete the old document; if that delete raises (raw collection, untyped — a broad catch is expected here) → best-effort delete of `new_id` (rollback; its own failure logged, labels only, not raised) and return False (record the residual both-versions case, if the rollback also fails, as a limitation);
   - return True only after both succeeded; the outer except and its log line stay for any other failure → False; the docstring no longer claims delete-then-re-add.
   - Considered and NOT used: `update_metadata` (a merge that swallows errors to False and would keep stale keys) — record why in the packet.
2. `update_tracking_metadata`: return the bool from `update_metadata` instead of True; when it is False, log one warning (labels only) and skip the success info log; every other path unchanged.
