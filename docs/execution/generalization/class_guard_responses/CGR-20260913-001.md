### Anchor #35 — `scripts/restore_backup.py`

Parent-reviewed and confirmed during this batch: `cmd_restore(name, apply)`
calls `_require_daemon_stopped()` after the dry-run return and before any
rename/copy. That function acquires
`utils.single_instance.acquire_single_instance_lock()`, exits 1 on
`SingleInstanceError`, and holds the lock for the life of the process — a
**stronger** guard than `daemon_running()` (it actively prevents Daemon from
starting mid-restore, rather than only detecting one already running), and
it sits at the script's only write path, so it also covers every direct
`cmd_restore` caller, not just the CLI.

Existing deployed evidence:
`tests/unit/test_sep09_backup_recovery.py::test_restore_refuses_when_daemon_lock_is_held`.

This batch adds one additional main()-level check, reusing that file's
`stores`/`backup`/`snapshot` fixtures by import (no edit to that file):
`TestRestoreBackupGuardEvidence::test_main_cli_refuses_when_daemon_lock_is_held`
in `tests/unit/test_script_apply_guards.py` — drives `restore_backup.main()`
via `sys.argv = [..., "--restore", name, "--apply"]` with the lock raising
`SingleInstanceError`, asserts `SystemExit` code 1 and the target data
snapshot unchanged. No source change was made to `restore_backup.py`.

The class-guard owner decides between a detector change (recognizing the
`utils.single_instance` lock pattern as an equivalent guard) or continued
`accepted_debt` for this anchor; this response does not add or modify any
disposition.
