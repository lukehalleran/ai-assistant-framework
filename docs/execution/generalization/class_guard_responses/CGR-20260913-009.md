### #139 — fixed, with deployed-function evidence

Before: `get_by_id`'s `except Exception: return None` (previously 509-510)
collapsed a genuine Chroma-read FAILURE into the same `None` returned for a
genuine not-found. Deployed-function proof: `test_failed_read_raises_retrieval_error`
drove the deployed `get_by_id` against a fake Chroma collection whose `.get()`
raises — on the unedited source this returned `None` silently (would have
passed a naive `assert result is None`); the NEW assertion
(`pytest.raises(RetrievalError)`) fails on unedited source and passes after
the fix.

After: `coll.get(...)` raising now raises
`RetrievalError(source="chroma_get_by_id", reason=type(e).__name__) from e`
— privacy-safe (label + exception class name only, never the exception
text; proven by `test_failed_read_raises_retrieval_error`'s message-marker
assertions). The genuine not-found path (`if not docs: return None`), the
unknown-collection path, and the found-dict shape are byte-for-byte
unchanged (`test_genuine_not_found_returns_none`, `test_found_returns_dict`,
`test_unknown_collection_returns_none`, all passing before and after).

### Claim-tracker sibling — no code change, evidence recorded

`ClaimIndex.cascade_staleness` (`memory/claim_tracker.py`, def 254; no CGR-009
anchor of its own) reads the failed doc via `chroma_store.get_by_id(...)`
inside its own `try/except Exception` (290-317). Before the store fix: a
failed read returned `None`, `existing = None`, and the `else` branch ran
"Document doesn't exist (deleted?), clean up index" →
`self.remove_document(doc_id)` — DELETING the index entry for a document
that still exists, on a merely transient read failure. After the store fix:
the raise now happens inside `chroma_store.get_by_id(...)`, which is called
from inside cascade_staleness's own `try`, so it lands in cascade_staleness's
own `except Exception as e: logger.warning(...)` — the `else`/`remove_document`
branch is never reached. No code change was needed in
`memory/claim_tracker.py`; its existing exception handling already does the
right thing once the store stops swallowing.

Deployed-function proof (through the REAL edited store, not a mocked
`get_by_id`): `TestCascadeStalenessRealStore::test_failed_read_retains_index_entry`
— on the unedited source this FAILS (`assert 'doc_1' in idx._doc_claims` →
`assert 'doc_1' in {}`, i.e. the entry was deleted); on the edited source it
passes (the entry is retained). A companion test,
`test_failed_read_warning_has_no_message_leak`, confirms via `caplog` that a
distinctive marker placed in the underlying exception's message never
reaches the claim-tracker's `logger.warning(...)` line — `str(RetrievalError)`
renders as `"chroma_get_by_id: RuntimeError"` (labels only), matching the
privacy contract of `utils.retrieval_outcome.RetrievalError`.
Paired mock-level controls (`TestCascadeStalenessMockedGetById`) confirm the
cascade's own exception handling in isolation: a raising `get_by_id` never
calls `remove_document` and returns no result entry for that doc; a genuine
