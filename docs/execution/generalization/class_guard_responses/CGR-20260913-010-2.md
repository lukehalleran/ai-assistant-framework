## Shutdown-time consumer: the count change

`ShutdownProcessor._extract_procedural_skills` (the only production caller
of `store_skill`, `memory/shutdown_processor.py` ~1036-1174) previously did
`doc_id = await self._storage.store_skill(skill); if doc_id: kept += 1` with
no try/except -- a raised `StoreWriteError` would have propagated out of
the whole method uncaught (it runs inside `asyncio.gather(...,
return_exceptions=True)` in Phase A, so it would have been swallowed as one
generic "extraction" LLM-failure log line for the WHOLE phase, silently
dropping every remaining skill in the same batch).

Now the call is wrapped: `except StoreWriteError: failed += 1; continue` --
the loop continues with the remaining skills, and the final log changed
from `if kept: logger.info(f"... {kept} procedural skill(s)")` to `if kept
or failed: logger.info(f"... {kept} procedural skill(s), {failed} failed")`
(counts only, no skill content). A dedup `None` (no raise) is still just
"not kept" and is never added to `failed`.

Deployed-function tests (`ShutdownProcessor` built via `__new__` with only
the attributes the method reads -- `model_manager`, `_storage`,
`corpus_manager`, `session_start`; a stubbed `model_manager.generate_once`
returning two valid procedural-skill JSON lines; a stubbed
`_storage.store_skill`):
- `test_one_failure_one_success_counts_both_no_exception`: first skill's
  `store_skill` raises `StoreWriteError`, second returns an id. Asserts the
  method does NOT raise, both skills were attempted (`call_count == 2`),
  and the log reads "Extracted 1 procedural skill(s), 1 failed".
- `test_dedup_skip_is_not_counted_as_failed` (control): first skill's
  `store_skill` returns `None` (dedup), second returns an id. Asserts the
  log reads "Extracted 1 procedural skill(s), 0 failed" -- the dedup skip
  is NOT counted as a failure.
- `test_all_healthy_control_kept_two` (control): both skills succeed.
  Asserts "Extracted 2 procedural skill(s), 0 failed".
