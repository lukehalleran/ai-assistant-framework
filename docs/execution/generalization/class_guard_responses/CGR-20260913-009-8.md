## Why a raise, not a typed `OutcomeList`

`store_result` calls `find_similar` with no try (line 107); `if similar:`
(109) takes the update-convergence branch, else inserts via
`add_to_collection` (127). A raise from `find_similar` leaves `store_result`
BEFORE the insert branch is ever reached — the correct fix for the
request's named real-defect row ("Synthesis `find_similar` failure stores
a duplicate instead of updating convergence"). An `OutcomeList` return
would not do this: `store_result`'s `if similar:` only tests truthiness, so
a failed-but-empty `OutcomeList` would be indistinguishable from a genuine
empty and would fall through to the insert branch, storing a duplicate —
exactly the bug being fixed.

`get_known_connections` (342-346), `get_ungraded` (450), `get_graded`
(470) and `get_audit_stats` (514) all call `get_all_results` with no try
and flatten/iterate its return value directly (a list comprehension, a
`for` loop, `len(...)`) — a raise reaches their own callers intact; a
returned `OutcomeList` would be silently flattened before any caller could
read `.status`. This matches F11a-1/F11b-1/F12c's same design decision for
other CGR-009 anchors (amendment "F12 split",
`docs/execution/generalization/failure_outcome_design.md`).
