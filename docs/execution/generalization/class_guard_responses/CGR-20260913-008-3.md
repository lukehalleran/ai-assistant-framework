## What changed (summary)

`knowledge/obsidian_manager.py`, at exactly the regions the F3b brief named
(17 changed lines: 12 insertions, 5 deletions):

  outcome_status` (the F1 leaf module).

  `return OutcomeList.unavailable("collection_unavailable")`; the success
  path returns `OutcomeList(scored[:limit])` instead of a bare
  `scored[:limit]` list; the `except Exception as e:` block keeps its
  existing `logger.warning` line byte-for-byte, then returns
  `OutcomeList.failed(type(e).__name__)` instead of `[]`.

  outcome_status(keyword_results)` immediately after the keyword call
  (before the combine step's `keyword_results[:keyword_limit]` slice, which
  would silently drop a list-subclass status). The combine/dedup logic and
  the image-loading block are byte-for-byte unchanged, and image loading
  still runs on `final_results` before any wrapping. If `kw_status` is
  `"failed"` or `"unavailable"`, returns `OutcomeList(final_results,
  status=kw_status, reason=f"keyword:{kw_reason}")` — the semantic leg's
  items are still kept (a partial read), only the status/reason reflect the
  keyword leg's failure. Otherwise returns `OutcomeList(final_results)`
  (status auto-derives `succeeded`/`no_results`). The outer
  `except Exception as e:` (covering a semantic-leg raise — see "Sibling
  determination" below, or an exception raised by `_keyword_search` itself)
  now returns `OutcomeList.failed(type(e).__name__)` instead of `[]`.
- `tests/unit/test_obsidian_failure_outcomes.py` (new, 255 lines) — drives
  the DEPLOYED `_keyword_search` and `get_notes` directly, with paired

  cases for the hybrid read, plus a dedicated privacy-leak test class and a
  read-only drive of the gatherer consumer. No network, no real ChromaDB or
  embedder (`MagicMock` stores throughout).

No other line in the file changed. Ranking, dedup, `limit` handling, image
loading, and every consumer outside this file are untouched.
