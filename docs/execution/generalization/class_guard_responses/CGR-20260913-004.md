- `core/safety_canary.py` — `_is_conversational(tone)` no longer tests
  `"conversational" in str(tone).lower()` (raw substring membership). It now
  normalizes `tone` (an `Enum` member → its `.value`; anything else →
  itself) and compares `str(normalized).strip().lower() == "conversational"`
  for exact equality. Added `from enum import Enum`. No other line changed;
  `observe()`'s broad `except Exception` (never raises) is untouched.
- `tests/unit/test_safety_canary.py` — added a parametrized deployed-function
  regression suite driving `SafetyCanary.observe` (not just the helper)
  across every `CrisisLevel` member, every `ToneLevel` member, conversational
  plain-string variants, non-conversational plain strings, and containment
  counterexamples; a mid-streak containment-reset test; and a
  never-raises test for unusual tone values (`None`, `int`, a bare `object`).
  Two now-redundant local imports inside the pre-existing
  `test_tone_encoding_agnostic` were removed in favor of the new top-level
  imports (no behavior change to that test).

## Anchor disposition — review #14, `core/safety_canary.py:49`

**Fixed** (real BC-01 instance; not a "not-an-instance" disposition). Old
code: `"conversational" in str(tone).lower()` — a raw substring test on the
lowered string form of whatever `tone` is. For the tone-encoding *values*
actually in production use (the four `CrisisLevel` values and the four
`ToneLevel` values), no false positive currently manifests, because no
non-CONVERSATIONAL member's `str()` form happens to contain the substring
"conversational" — but the mechanism is unsound generally and the class
catalog's Find line requires `.value` equality, not containment. Evidence of
the actual defect: a plain string such as `"not conversational"`,
`"conversational_extra"`, `"inconversational"`, or a sentence merely
mentioning the word, is wrongly admitted as conversational by the old code —
proved by running the new parametrized tests against the unpatched source
(see "Focused test command" below): those five test cases failed on the
unpatched `core/safety_canary.py`, each showing `observe()` returning a
fired `SAFETY_CANARY_TONE_FLATLINE` event where it must return `None`.

No site was left unfixed.
