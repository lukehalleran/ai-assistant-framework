## What changed (summary)

`knowledge/web_search_manager.py`, at exactly the regions the F2 brief named
(89 changed lines: 73 insertions, 16 deletions):

- One new import: `from utils.retrieval_outcome import OutcomeList,
  RetrievalError` (the F1 leaf module; F2 is its first production adopter).
- One new optional field on `WebSearchResult`: `extract_error: Optional[str]
  = None`.
- `_tavily_search` (anchor **#110**, was line 1538): the no-client branch now
  `raise RetrievalError(source="tavily_search", reason="client_unavailable")`
  instead of `return []`. The `except Exception as e:` block keeps its
  existing invalid-key detection and `self._api_key_invalid = True` and log
  lines byte-for-byte, then raises `RetrievalError(source="tavily_search",
  reason="invalid_api_key" | type(e).__name__) from e` instead of
  `return []`. The success path (including a genuine empty
  `{"results": []}` response) is untouched.
- `_tavily_extract` (anchor **#111**, was line 1744): the no-client and
  empty-`urls` checks are split — `if not urls: return []` first (a genuine
  no-op stays a no-op, even with no client), then `if not self._tavily_client:
  raise RetrievalError(source="tavily_extract", reason="client_unavailable")`.
  The `except Exception as e:` block mirrors `_tavily_search`'s change
  exactly (same invalid-key detection/flag/log lines preserved, then
  `raise RetrievalError(source="tavily_extract", reason=...) from e`).
- `_execute_search` (the three wrapper call sites):
  - Step 1 (`_tavily_search`) is now wrapped in `try/except RetrievalError`:
    if `self._api_key_invalid`, returns EXACTLY today's
    `WebSearchResult(error="Tavily API key is invalid")`; otherwise returns
    `WebSearchResult(error=f"Web search provider failed ({e.reason})")`, no
    query text. Both returns skip `record_usage` exactly like today's
    invalid-key early return — the reservation's `spend(1.0)` (already
    committed before the call dispatched) is what actually charges the
    credit, via `search()`'s `finally: reservation.settle()`.
  - Step 2 (`_tavily_extract` for STANDARD/DEEP) is wrapped in
    `try/except RetrievalError`: on failure the already-fetched search pages
    are kept, `extract_error = f"tavily_extract:{e.reason}"` is recorded, one
    `log.warning` is emitted with no URL/query text, and
    `session.credits_used` is still incremented (the call was dispatched and
    billed regardless of outcome). `error` stays `None`.
  - Step 3 (DEEP link-following extract) gets the identical
    `try/except RetrievalError` treatment, only overwriting `extract_error`
    if Step 2 did not already set it.
  - The final `WebSearchResult(...)` return now passes
    `extract_error=extract_error`.
- `fetch_url_content`: the inner `tavily = await self._tavily_extract([url])`
  call is wrapped in `try/except RetrievalError` (the reservation's
  `finally: settle()` is unchanged and still runs on every exit). On
  failure: if the free direct layer already produced a page, that page is
  returned unchanged (today's preference is kept); otherwise
  `OutcomeList.failed(f"tavily_extract:{e.reason}")` is returned instead of a
  bare `[]`. The budget-refusal paths (`FetchedPages(blocked="budget")`,
  both the pre-reserve and refused-`spend()` cases) are untouched.
- `tests/unit/test_tavily_failure_outcomes.py` (new, 339 lines) — a
  deployed-function regression suite driving `_tavily_search`,
  `_tavily_extract`, `search()`, `_execute_search`'s STANDARD-depth partial
  path, and `fetch_url_content` directly, plus two deployed-consumer drives
  (`core/agentic/tools.py::ToolExecutor._execute_fetch_url` and
  `core/prompt/gatherer_web.py::WebSearchMixin._get_web_search_results`) with
  no edits to either consumer file. No network, no LLM call, no `pip
  install`; only the Tavily provider client's `.search`/`.extract` methods
  are faked.

No other line in the file changed. `multi_search`, the reservation/credit
machinery, the cache, `fetch_url_content`'s budget paths, and every consumer
outside this file are untouched — see "No other behaviour change" below.

## `multi_search` sibling (BC-47, not a candidate anchor, report only)

`WebSearchManager.multi_search` (≈2271–2475, not a source path in this
request's candidate-anchor table and not edited by this batch) has the same
"aggregation keeps an error only when the merged result is empty" shape as
BC-47's mechanism: `error="; ".join(errors) if errors and not all_pages else
None` (≈2472) drops a per-sub-query provider failure the instant ANY other
sub-query returned pages — the joined `errors` string, and with it any
sub-query-level `RetrievalError` this batch's wrappers now raise, is silently
discarded. This is distinct from the already-fixed 2026-09-12 budget-refusal
case (`blocked="budget"` survives aggregation via a separate typed field);
here only `error` carries the information, and it is lost. Recorded here per
the F2 brief; no code changed for this sibling in F2 — it is a candidate for
a future batch/request, not something this response closes.
