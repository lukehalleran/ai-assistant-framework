## What changed and why

**Before D5:** R06 followed the parent brief's contract and made `has_thread_break_marker` negation-aware (`has_non_negated_hit` with the shared cue list).

**Parent review finding.** The shared cue list includes `never`, `stop`, `skip`, `avoid`, `rather than` and `instead of`, checked over the 5 tokens before the hit, across punctuation. In chat these cues routinely come right before a real topic change:

- "never mind, moving on…"
- "ok stop, different topic…"
- "skip that. new question…"
- "rather than that, switching gears…"
- "instead of that, changing topics…"

**Consequences.**

- **Missed breaks.** A missed marker means `calculate_thread_continuity_score` no longer returns 0.0 ("explicit break markers override everything"), so `belongs_to_thread` → `memory/thread_manager.py` continues the previous thread and keeps its context.
- **Little protection in return.** Bare "not" is not a cue, so negation protected only rare forms such as "not going to keep changing topics".

**D5 fix.**

- `has_thread_break_marker` now returns `_THREAD_BREAK_MATCHER(query_lower)`: negation-INSENSITIVE, still word-bounded.
- The `has_non_negated_hit` import was dropped, and the original single-line import restored.
- The comment and docstring now state the policy and the reason.
- No vocabulary change (BC-76).
