## Per-anchor disposition (deployed-function evidence)

All three are real BC-01 instances (not "not-an-instance" dispositions), and
the deployed-function tests prove the pre-patch defect directly (see
"Focused command" below for the actual failing-before run).

- **#15** `knowledge/git_memory.py:364`, `if "wip" in subject_lower:`.
  Old code: `"wip"` is a substring of `"swipe"` (`"swipe"[1:4] ==
  "wip"`), so `_extract_tags("swipe to dismiss")` wrongly returned
  `work-in-progress` — the request packet's own example. Also reproduced
  for `"wipe the board"` and `"unwip"`. **Fixed**: the deployed
  `_extract_tags("swipe to dismiss")` (and the wrapped/indented
  `"swipe\n  to dismiss"`) no longer carries the tag; `"WIP: partial
  refactor"` (the pre-existing `tests/test_git_memory.py` control) and the
  batch's own `"wip: quick patch"` / `"a wip feature"` / wrapped
  `"WIP:\n  partial refactor"` still do.
- **#16** `knowledge/git_memory.py:366`, `if "breaking" in subject_lower:`.
  Old code: `"breaking"` is a substring of `"groundbreaking"`, so
  `_extract_tags("groundbreaking results")` wrongly returned
  `breaking-change` — the request packet's own example (also reproduced for
  `"unbreaking"`). **Fixed**: the deployed call (clean and wrapped
  `"groundbreaking\n  results"`) no longer carries the tag; `"breaking
  change to the parser"` and the pre-existing `tests/test_git_memory.py`
  control `"feat!: BREAKING change to API"` still do.
- **#17** `knowledge/git_memory.py:368`, `if "hotfix" in subject_lower:`.
  Old code: `"hotfix"` is a substring of `"hotfixture"`, `"hotfixation"`,
  and `"nonhotfix"`, so each wrongly returned `hotfix`. **Fixed**: none of
  the three carry the tag deployed; `"hotfix for login"`, `"a hotfix"`, and
  the sense-preserving inflection `"hotfixes"` (verified against the
  deployed `utils.trigger_match` chokepoint before writing the fixture —
  `"hotfixes"` and `"hotfixing"` both hit, `"hotfixture"`/`"hotfixation"` do
  not, because `-es`/`-ing` are declared sense-preserving suffixes and
  `-ture`/`-ation` are not) still tag.

No site was left unfixed. No new phrase or keyword was added to or removed
from the tagged vocabulary (BC-76): the same three literals (`wip`,
`breaking`, `hotfix`) are matched, only the matching mechanism changed.

## Limitations

- This is deterministic unit-test evidence only ("focused contract green");
  it is not a synthetic assembled probe, owner canary, or population claim.
- Deliberately no new conventional-commit `!:` breaking-marker semantics was
  added, per the parent's contract: a subject like `"feat!: refactor
  config"` (a `!:` marker with no literal "breaking" word) still gets no
  `breaking-change` tag, same as before this batch. This is recorded as a
  limitation, not silently expanded scope.
- Plain boundary matching only; `_extract_tags` still applies no negation
  semantics (verified directly: `"do not merge, this is not wip"` still
  tags `work-in-progress`) — tag metadata is not a request cue, so
  `utils.trigger_match.is_negated`/`find_hits`/`has_non_negated_hit` are
  deliberately not used here, only the boundary-matching half of the
  chokepoint (`compile_keyword_matcher`/`KeywordMatcher.iter_hits`).
- `utils.trigger_match`'s bare-word morphology bound (suffix list
  `s/es/ed/d/ing/ings/ness/ly/ity/ful`, plus the three regular English
  stem-alteration rules) is a hand-written approximation, not a stemmer or
  lexicon (per BC-01's own catalog status: "partial"). A real-world commit
  subject using an inflection outside that list (none identified for
  `wip`/`breaking`/`hotfix` during this review) would not tag; this is the
  same known limitation as every other chokepoint adopter, not new to this
  fix.
- BC-58 sibling search (below) found one raw-membership site outside this
  request's file ownership (`utils/tone_detector.py:1023`); it is reported
  only, not fixed.
- No live Daemon process was started or exercised; `data/`
  (`benchmark_per_case.csv`, `chroma_db_v4`, `embedding_migration_manifest.json`,
  `pipeline`) was unchanged before and after every command in this batch; no
  network call, credential, or provider was used.
