# Model integration plan

1. Read the clone's model registry, capability classifiers, sync/async generation paths, chat/tool path, and GUI/API model-listing paths without editing reserved files.
2. Verify each requested OpenRouter slug and the provider-facing capabilities, context window, parameter constraints, and tool-call compatibility against current provider documentation and public metadata.
3. Decide whether each requested model can truthfully use every existing generation path. Keep existing defaults and reasoning-empty-content recovery behavior intact; document any API limitation that cannot be resolved within the reserved-file boundary.
4. Construct a unified diff in memory only, with explicit alias registration, declared capability/context rows, and all required classifier/request-path updates. Save the diff as `model_integration.patch`; never apply it.
5. Add focused standard-library checks under `model_patch_checks/` that apply the candidate diff to source text in memory, validate the candidate AST/registry/classifiers/context/parameter filters, and execute extracted candidate request methods against fake transports to inspect actual kwargs.
6. Record source base hash, provider citations, exact proposed paths, validation results, and gate limitations here. The parent owns test execution; send the exact 512 MiB systemd command and do not run checks locally.
