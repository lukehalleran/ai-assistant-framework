## Observed shape and semantic risk

Each script declares `--apply` and writes a Daemon store (profile/facts collections, the graph JSON, proposal metadata, a backup restore) without ever calling `utils.daemon_guard.daemon_running()`. A live Daemon re-saves its in-memory state on shutdown and silently clobbers or resurrects the script's changes (BC-37 incidents 2026-08-05 and 2026-09-05). The other sixteen `--apply` scripts already carry the guard.

This is a bounded structural review, not a reproduced runtime failure. If
the source owner shows a site is not an instance of the class, the response
should say so with deployed-function evidence. The class-guard owner then
decides between a detector change and continued accepted debt.

## Requested remedy (the source owner owns the design)

Add the repository's reviewed guard shape so it runs before every statement that consumes the `--apply` value: `if args.apply and daemon_running(): <refuse>` (or a module wrapper `def _daemon_running(): ... return daemon_running()`), refusing with `return 1`/`sys.exit(...)`. Keep dry runs unguarded. `restore_backup.py` passes `apply=args.apply` into `cmd_restore`; the guard belongs in `main` before that call.

## Expected deployed-function regression tests

For each script, drive its deployed `main()` with `--apply` while `utils.daemon_guard.daemon_running` is patched to return True, and assert a non-zero refusal with the store writer never called (patch the writer or point it at tmp). Control: the same invocation with the guard patched False reaches the writer; a dry run never consults the guard's result for refusal.
