## Observed shape and semantic risk

The system appends text to assistant replies at delivery (`> ⚠️ …` guard
notices) and at read time (`[Personal-claim check: …]`, `[unverified action
claim]`). Downstream consumers then read the reply as if the bytes were the
model's answer: a dedup key hashed the marker (BC-20 reopened), an audit
judged the notice (BC-45), a render fed the notice back to the planner and
the next prompt (BC-75). Lane GF fixes the four known sites through one leaf
module; nothing stops the NEXT consumer from reading `display_output` /
`response` raw, and nothing stops a NEW emitter from writing a notice the
leaf's stripper does not know.

## Requested detector

Static, stdlib-only, gate:

1. Every call to the delivery checks receives the pre-suffix text (a name
   never rebound through `… + <suffix>`), and the sequential revisions compose
   (the personal-claim check reads the grounding-revised body).
2. Every identity key built over a stored turn in `core/prompt/` goes through
   `_canonical_turn_key`.
3. Every render of a stored assistant turn strips delivery notices before its
   annotator.
4. Every `> ⚠️` emitter routes through `utils/read_time_markers.py` (new
   emitters must register).
